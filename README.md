# Moe Need Marks

SPT **4.1.5** 的任务与藏身处物品需求标记模组，版本 **1.0.5**。客户端和服务端必须同时安装。

## 安装

将 `Moe-NeedMarks-1.0.5-SPT4.1.5.zip` 解压到游戏根目录，保留目录结构：

```text
BepInEx/plugins/Moe-NeedMarks/MoeNeedMarks.Client.dll
SPT_Runtime/user/mods/Moe-NeedMarks/MoeNeedMarks.Server.dll
SPT_Runtime/user/mods/Moe-NeedMarks/MoeNeedMarks.Shared.dll
SPT_Runtime/user/mods/Moe-NeedMarks/MoeNeedMarks.Server.deps.json
```

重启服务端和游戏后生效。打开 F12，在 **Moe Need Marks** 下调整配置。卸载时移除上述两个专属目录；配置位于 `BepInEx/config/moe.needmarks.cfg`，可保留以便重装。模组不建立提交历史数据库，不修改任务、物品或存档。

不要与 MoreCheckmarks 同时启用：两者管理同一个原生勾，插件元数据已声明冲突。需求信息直接追加在原生物品悬浮提示内部，沿用原有字体、背景及定位，保留其他模组追加的价格和交易标记文本。

## 使用规则

- 商店页面物品悬浮提示同样显示需求明细及汇总，沿用现有 F12 开关，保留原生价格和交易状态；商人货架数量不会计入“当前已有”。

- 已完成任务／已建造设施阶段用深灰色显示；其余无需 FIR 的需求用灰蓝色显示，需要 FIR 的未完成需求保持原色。周期任务名称与游戏一致（例如“寻物上交”）。

- **黄勾**：当前物品是 FIR，并且存在尚未交满、要求 FIR 的任务目标。
- **蓝勾**：当前物品是 FIR，并且存在尚未提交、要求 FIR 的设施建造或升级需求。
- **绿勾**：以上两种需求同时存在。F12 可分别修改三种颜色。
- 库存备齐不会消勾；交满相应目标且没有其他未来需求后才消除该需求颜色。普通 FIR 物品恢复白勾，特殊任务物品保留原生标识。
- 非 FIR 物品仍然显示需求明细和库存数量。库存总数不表示这些物品全部符合任务的耐久、FIR、狗牌等级或枪匠改装要求。
- 保持鼠标悬浮在物品上，滚轮查看原提示内超出限高区域的全部内容。切换物品后从顶部开始，关闭提示时恢复原生布局。
- 顺序为：原有提示 → 任务需要及明细 → 藏身处需要及明细 → 当前已有 → 总共需要。关闭某个显示项后，其余项目保持此顺序。
- 任务、藏身处、底部汇总三个区块之间各留一行空行；“当前已有”和“总共需要”连续显示。隐藏整个区块时不保留多余空行。
- 不被任何纳入统计的任务或设施阶段需要的物品，不显示需求区块和“当前已有”。仍有历史需求的物品可以显示。
- 明细采用短格式：`[未接取] 任务名 (0/3)`、`[已接取] 任务名 (1/3) FIR`、`[未建造] 情报中心 3级 (0/2)`、`[已建造] 设施名 1级 (2/2)`。FIR 仅在该目标要求战局内找到时显示；已完成、可完成和建造中保留独立状态。
- 例如本地 4.1.5 的加密磁带盒用于情报中心 3 级，需求为 **2 个**，不是两个设施阶段；该配方 `isSpawnedInSession=false`，因此只有原生白勾。有数量需求不等于有 FIR 需求。

### 汇总

设任务已提交量为 Q，设施已提交量为 H，随身为 B，仓库为 S，任务和设施总需求分别为 TQ、TH：

| 显示 | 公式与示例 |
| --- | --- |
| 任务需要 | `(Q+B+S)/TQ`，例如 `任务需要 (12/15)` |
| 藏身处需要 | `(H+B+S)/TH`，例如 `藏身处需要 (12/15)` |
| 当前已有 | `(B+S) 合计`，例如 `当前已有 (5+6) 11` |
| 总共需要 | `(Q+H+B+S)/(TQ+TH)`，例如 `总共需要 (18/26)` |

随身按当前玩家装备树递归统计，包含穿戴装备、背包、弹挂、口袋、安全箱、嵌套容器及附件。仓库包含嵌套容器和整理台；不包括商人、邮件、他人物品或设施生产槽。堆叠按数量计算，物品 ID 去重。战局内随身实时读取，仓库独立取服务端快照，不重复叠加入场前装备。分子不封顶；无对应需求时不显示该需求汇总。

### 任务范围与分支

普通上交默认启用。枪匠整枪、地图埋放、安装信标分别提供开关，默认关闭。单纯寻找目标不重复计算；枪匠开关仅统计整枪，不推算配件。

包含历史已完成、当前可接取、进行中、可完成及未来可达任务。排除其他阵营、版本不适用、永久不可达、已失败任务和未开放活动的未来需求；已完成活动任务保留。

日周常默认包含本周期可接取、已接取和已完成任务；“日周常仅包含已接取”会排除尚未接取的任务。旧周期、未生成或不可接取的日周常不纳入统计。

互斥分支尚可选择时，对每种物品取可行分支总量的最大值。例如 A 分支要 a×1、b×2，B 分支要 a×2、c×1，汇总为 a×2、b×2、c×1。各分支明细保留原值，共同前后置不重复计数。接取任务本身不会提前锁定分支；当实际完成／失败状态导致其他分支不可达时才排除。

允许替代提交的物品共享目标进度。例如「惩罚者 - 5」要求普通 PM／PM(t) 合计两把，已交普通 PM 一把、仓库有 PM(t) 一把时，在 PM(t) 上显示 `任务需要 (2/2)`，明细标注“任选／共享进度”。这不表示历史上提交过 PM(t)，也不会把其他候选型号的库存混入当前已有。

### 藏身处历史

统计设施所有等级的建造与升级配方，不含生产、燃料等运行消耗。旧存档没有完整消耗流水，历史已提交量按**当前配方和已建等级**推算，包含初始等级。施工开始已扣除的材料立即计入，施工完成时不重复增加。更改配方、修改设施等级或使用赠送高级设施的存档，均会影响推算值。

### F12 配置

配置即时生效并保存：任务／设施勾开关、三种颜色、四项汇总开关、任务／设施明细开关，以及未来、可接取／待建、进行中／施工中、历史明细开关。

“显示”开关只控制画面，不改变统计。枪匠／埋放／信标和日周常范围选项会同时影响明细、统计与勾。界面使用中文，任务和设施名称遵循游戏语言。

## 构建与验证

需要 .NET 10 SDK 和本地 SPT 4.1.5 客户端。开发目录之外的游戏程序集不随源码或安装包分发。

```powershell
./Package.ps1 -SPTPath 'G:\Tarkov\2026.09.05\客户端'
./Package.ps1 -SPTPath 'G:\Tarkov\2026.09.05\客户端' -Install
./Verify-Server.ps1 -SPTPath 'G:\Tarkov\2026.09.05\客户端'
```

`Package.ps1` 编译、运行测试、检查程序集版本并生成带 SHA256 校验的安装包。`-Install` 只安装本模组文件，不停止现有游戏或服务端。集成测试读取本地数据库和存档，支持环境变量 `NEEDMARKS_SPT_PATH`；不具备游戏环境时可用 `dotnet test Tests/MoeNeedMarks.Tests.csproj --filter 'Category!=SPT415'` 运行纯逻辑测试。

`Verify-Server.ps1` 创建隔离的服务端、配置与存档副本，与现有服务端模组一同加载，使用独立端口读取快照，并在结束时停止自己启动的进程。大体积只读数据库／资源通过目录联接复用；运行产物位于 Git 忽略的 `verification/runtime`。

验证情况与游戏内人工验收项见 [verification/验收记录.md](verification/验收记录.md)。

## 实现说明

客户端：BepInEx 5 / Harmony / .NET Framework 4.7.2。服务端：SPT 4.1.5 / .NET 10。共享逻辑层不依赖 Unity。

只读接口 `/moe/needmarks/snapshot` 使用 SPT 会话认证，返回协议版本 1 的角色需求、任务前置／失败关系、目标计数、设施阶段和仓库物品。数据来自运行时表；定义缓存最长 30 秒，界面活跃期间状态每两秒异步同步，本地任务与库存事件驱动显示刷新。同步及配置刷新期间保留旧计算结果，新结果就绪后一次替换；网络失败保留同角色最近有效快照。原生文本一次写入完整内容，相同内容不会反复拆除再追加。角色切换清空缓存，旧请求结果不得跨角色使用。

参考：[TommySoucy/MoreCheckmarks](https://github.com/TommySoucy/MoreCheckmarks) 的彩色标记和需求提示交互。本项目独立实现统计、任务路径、接口和 UI，未复制其代码或图片资源。
